## 1. Right-sidebar tab-type registry — yes, a third-party plugin can add a "Git" tab

- The right Sidebar owns the registry and the per-session surface: "It holds one docking surface per session … and owns the navigation controller (`ctx.sidebarRight`), the tab-type registry (`ctx.sidebarRightTabs`), and the Tab domain" (`ASAR/dsh-client-ui-sidebar-right/README.md:12`). It is provided as a Cordis service by that package: `ctx.reflect.provide("sidebarRightTabs", tabs)` / `ctx.reflect.provide("sidebarRight", controller)` (`ASAR/dsh-client-ui-sidebar-right/lib/client.js:5599-5600`).
- **A tab type registers in two stages, and "the shipped guide type goes through exactly the same public path a type from another package does (`ui-sidebar-documentpreview` is the live proof)"** (`README.md:83`):
  1. `ctx.sidebarRightTabs.register({ id, kind, patterns?, priority?, canOpen?, title, guide?, keepMounted?, multiple? })` — static declaration, returns disposer; `id` unique across registrations (a package name); `patterns` are globs over `dsh-resource://` addresses; a page type names no patterns and opens by `kind`; `canOpen(address)` vetoes; `title(address)` captured at open time; `guide` contributes start-page cards; `kind` holds at most one `builtin` and one `extension` registration, the extension wins while live (`README.md:85`). Two real shipped calls: forge `ctx.sidebarRightTabs.register({ id: TAB_ID, kind: TAB_KIND /* "forge-panel" */, title: () => t("tab.title"), guide: [{ id: "review", order: 15, … }] })` (`ASAR/dsh-experimental-client-ui-forge/lib/client.js:11397-11399,11655`) and its resource type `changesDefinition` = `{ id, kind: "forge-changes", keepMounted: true, patterns: [`${PREFIX}**`], canOpen: addr => parseChangesAddress(addr) !== undefined, title }` (`:3406-3408,3465`). Files: `{ id: FILES_ID, kind: FILES_KIND, priority: "builtin", title, guide: [{ id:"workspace", order:10, … }] }` (`ASAR/dsh-client-ui-sidebar-files/lib/client.js:22-30`).
  2. The body: `ctx.slots.register({ name: 'sidebar.right.pane.tab', key: definition.id }, Body)`; it reads `{ sidebar, panel, tab, navigation, signal, actions }` via `useTabInfo()` and `tab.actions.openResource/openTab/close` (`README.md:86,92-106`). Keyed catalog entry: `ASAR/dsh-cordis-client-runner/lib/client.js:6326-6382` (`key` required, session scope; occupants at `:6364-6378`).
- Extra seats: `sidebar.right.pane.tab.title` (keyed, optional live title, `:6384`), `sidebar.right.tab.menu.item` (list, tab-menu actions, owner props `{tab, dismiss}`, `:6890-6946`), `sidebar.right.tab.guide` (chain, replace the guide body, `:6753-6795`), guide entries/actions. "No seat exists for pane-level actions or for collapsed-state controls" (`README.md:90`).
- Constraints: per-session only — "No surface without a session" (`README.md:152`); titles fixed at open time unless a title seat registers (`:156`); `multiple: true` gives independent instances (`:125`); `keepMounted` retains bodies (`:112`). A third-party type must inject `["slots","locale","sidebarRightTabs","sidebarRight"]` (compare `ASAR/dsh-experimental-client-ui-forge/lib/client.js` inject list, and `ASAR/dsh-client-ui-sidebar-files/lib/client.js` inject list).
- Is the right sidebar active here? Yes: `@deepseek-ai/dsh-web-app` inserts `ui-sidebar-right` (`ASAR/dsh-web-app/cordis.patch.yml:279-280`), `ui-sidebar-files` (`:299-300`), `ui-sidebar-documentpreview` (`:288`), `ui-sidebar-browser` (`:292`), `ui-sidebar-terminal` (`:296`), `ui-deliverables` (`:357-358`). Shipped tab types recorded in the catalog: guide, files, documentpreview (`text`, fallback band), browser, terminal, deliverables `changes-review`, subagent chat, plan preview, schedule task, plus the experimental forge `forge-panel` + `forge-changes`. (Other catalog occupants — liveshare, session inspector — belong to bundles not selected in this profile.)

## 2. Reusable file tree — `sidebar.files.tree` Factory: yes, and it is explicitly meant for this

- `ASAR/dsh-client-ui-sidebar-files/README.md:77`: "To draw workspace listings, **changed files, or local diffs**, declare `const TREE_OPTIONS = { slots: { accessory: ModuleLevelComponent }, fallback: null }` at module scope, then call `renderFactorySlot('sidebar.files.tree', input, TREE_OPTIONS)`. … The root-scoped Factory is available only while the files plugin is loaded; without it, `renderFactorySlot` renders the supplied `fallback`, or nothing when omitted. Import declarations and `FileTreeInput`… **type-only** from `@deepseek-ai/dsh-client-ui-sidebar-files/client`; no component value is exported."
- `FileTreeInput` = `{ root, entries, expanded, onToggle(entry, expanded), onOpen(entry), directories?, current?, currentRef?, canOpen(entry)?, rowTriggerProps?(entry, kind) }` (`README.md:79`). "A `TreeEntry` is `{ path, name, meta?: { kind?, hidden?, size? } }` … Missing intermediate directories are added once … directories first, then natural case-insensitive name order" (`:81`). Local `accessory` slot (root scope, owner props `{ entry }`) renders beside each row (`:83`). "The Factory owns loading, empty, truncated, and unavailable copy … callers own data access, expansion, opening, ancestor reveal, and scrolling" (`:79`).
- Mechanics: `renderFactorySlot` is a **slot-injected prop**, not an import — `PropsRenderFactories { renderFactorySlot: RenderFactorySlot }`, and every slot component's props include it (`ComposedProps = PropsRuntime & PropsRenderSlots & PropsRenderFactories & …`, `ASAR/dsh-cordis-client-runner/lib/client.js:2234,2285-2286` and the `ComposedProps` declaration in the same file). The Factory itself is registered by the files package with `ctx.slots.registerFactory({ name, scope, … }, Component)` (`ASAR/dsh-client-ui-sidebar-files/lib/client.js:2208,2214,2221`; API `RegisterFactory`/`RegisterFactoryOptions` in the catalog) and consumed via `renderFactorySlot("sidebar.files.tree", …)` (`:1688`) and `"sidebar.files.navigator"` (`:1748`).
- So a Git panel inside a `main` panel or a `sidebar.right.pane.tab` body can render the shipped tree with arbitrary entries (changed file lists, per-repo flat trees, repo listing), own the data/open behavior, and add per-row accessories (e.g. status letter, stage button). Catches: (a) the Factory disappears if `ui-sidebar-files` is composed out — pass `fallback`; (b) no built-in search/rename/drag (`README.md:97`) and one root per render (`:98`); (c) type-only imports mean the plugin builds as plain JS (its own `lib/client.js`), as all shipped client plugins do.

## 3. What UI already renders file content and changes/diffs

- **File preview** — `ui-sidebar-documentpreview` (`ASAR/dsh-client-ui-sidebar-documentpreview/README.md`): type id `@deepseek-ai/dsh-client-ui-sidebar-documentpreview`, kind `text`, fallback band, file-resource patterns, `canOpen` accepts Session addresses only (`:33`); body under the keyed seat; shared loader/controls; renderers for Markdown/code (paged text via `remote.workspaceFiles.read`), images, PDF, Office, HTML, Excel plus plain-text fallback (`:12,37,58-64`). It is **preview only**: "Preview, not editing. The viewers provide no file editing or shared search interface" (`:144`); it renders no diffs. It also renders `sidebar.files.navigator` beside every preview and exposes `sidebar.right.tab.document.actions` / `.unpreviewable` (`:34`). Address form `dsh-resource://file/session/<sessionId>/<path>` (`ASAR/dsh-api-workspace-files/README.md:12`, section "Client file resources").
- **Turn changed-files card + review tab** — `ui-deliverables` (`ASAR/dsh-client-ui-deliverables/README.md:12,45,47-49`): the card lists files a turn changed with counts and opens the turn's `changes-review` tab in the right Sidebar; hovering a row 500 ms shows an inline comparison preview (`:45`). The review tab does **unified and side-by-side** diffs with old/new line numbers, per-hunk Shiki highlighting, wrap toggle, open-in-app, 5,000-line draw cap, binary/oversized/one-line fallbacks (`:49`). It is a shipped tab type at the `builtin` band for `dsh-resource://changes-review/session/<sessionId>/<seq>/<turn>`, opened via `ctx.sidebarRight.openResource` (`:67`). Data comes from the Host over authenticated routes — `CHANGED_FILES_PATH="/api/changes.summary"`, `CHANGES_DIFF_PATH="/api/changes.diff"`, `CHANGES_OPEN_PATH="/api/changes.open"`, registered with `ctx.connection.fetch.register(...)` (`ASAR/dsh-client-ui-deliverables/lib/index.js:4-8,49-90`).
- **Other diffs** — `ui-deliverables` comparisons are turn-start vs turn-end snapshots, not working-tree diffs. The only Git working-tree diff UI is experimental **forge** (see §5): "Local changes card" and the `forge-changes` "Changes view" with Branch/Uncommitted/Unstaged/Staged scopes (`ASAR/dsh-experimental-client-ui-forge/README.md:39-40`), read-only. There is **no** other shipped diff renderer, and no image/binary/3-way/merge-conflict diff UI.
- So today a user can already: preview any Session-workspace file in the right Sidebar, see a turn's changed files with a diff review tab, and (with forge active) see local changes for the Session's checkout in scopes including Staged vs HEAD. There is no repo-picker/branch/staging-surface and no diff view for an arbitrary repo outside the current Session.

## 6. Constraints for a custom main-panel Git page

- Entry: `ctx.slots.inject('sidebar.panellist', () => ctx.slots.register({ name:'sidebar.panellist', id:'git-panel', order: 100, label: () => t('panel') }, GitIcon))` + `ctx.slots.inject('main', () => ctx.slots.register({ name:'main', key:'git-panel', locale: NS }, GitPage))`; panellist `id` must equal the `main` key, and selecting an unregistered key throws (`ASAR/dsh-client-ui-sidebar/README.md:42`; `ASAR/dsh-client-ui-layout/lib/client.js:522-523`). Install-time examples: `PROFILE/dsh-superagent` (link) and the guizang plugin.
- **Two panels coexist**: the `main` panel replaces only the center column; the right Sidebar is an independent per-session column/seat (`ASAR/dsh-client-ui-layout/README.md:30-38`; `ASAR/dsh-client-ui-sidebar-right/README.md:12,59,63`). A Git main panel and a Files/Terminal right tab can be open at once. The reverse (Git as a right tab) is also possible (§1).
- Client bundle: prebuilt plain-JS `lib/client.js` registering `window.__ModuleLoader__.load({ id:<pkg>, factory(require){ … return { isPlugin, inject, apply } } })`; React from the frozen module table (`SKILL/references/ui-plugin.md:9`); `dsh.client.external` only for non-baseline imports; no imports of Harness client packages (`SKILL/references/practices.md:35`); size is whatever you ship (observed shipped bundles 245 KB–916 KB, no documented cap); theme tokens only, no iframes for pages (`practices.md:33-34`).
- Colors: use `--dsw-alias-file-diff-added-bg|-added-gutter|-added-marker`, `--dsw-alias-file-diff-deleted-*` (the shipped diff palette; `ASAR/dsh-client-ui-theme/README.md:68` "design-platform.css also owns … the `--dsw-alias-file-diff-*` code, gutter, and marker palette for file comparisons"; the forge CSS uses exactly these, `ASAR/dsh-experimental-client-ui-forge/lib/client.js:4466`), plus `--dsw-alias-label-*`, `--dsw-alias-border-l*`, `--dsw-alias-state-success/error-primary`, `--dsw-font-markdown-code-block`, `--dsw-radius-*`.
- Settings persistence: declare a Schemastery `Config` on the Host row (validated at activation; user-editable in `cordis.patch.yml`), and after `apply` persist changes with `ctx.settings.update(ns, patch, revision)` or `ctx.configEditor.edit(entry, change)` — never rewrite the profile patch by hand (`SKILL/references/host-plugin.md` "Persist your own configuration"; host `settings`/`configEditor` contracts above). Viewer-only prefs (tree width, selected repo, diff layout) can live in `localStorage` keyed per browser, as the right Sidebar does (`dsh.sidebar-right.v1.<sessionId>`, `ASAR/dsh-client-ui-sidebar-right/README.md:76`).

## 7. Architecture sketch

**Recommended: main-panel Git page + own 3-column layout, one host services package.**

- Host half (`GitService`, packages `dsh-git-panel`): `inject: ['connection','subprocess','fs','workspaceFiles','workspaceRegistry','sandboxPolicy','workingDirectory','settings']`; register authenticated routes with `ctx.connection.fetch.register({ path:'/api/git-panel/<op>', methods:['GET','POST'], requestBody:'buffered', fetch })`:
  `repos.list` (registry workspaces + config repos), `repos.add` (via `directoryPicker`/validated path + `git rev-parse --show-toplevel`), `status` (porcelain v2 + branch + ahead/behind), `branches`, `worktrees.list/add/remove`, `log`, `diff` (path + scope: worktree/index/HEAD/fork-point; `git diff --no-ext-diff --no-textconv --no-color -M`, cap bytes/hunks; detect binary via NUL probe), `stage`/`unstage`/`discard` (explicit user actions only), `tree` (`ctx.fs.listDir` for repo browsing), `file` (`ctx.fs.readText` with size cap). Resolve `sandboxPolicy.resolve({session})` and confine Git to the repo root; reuse `ctx.subprocess.resolveExecutable('git')` and a fixed timeout/output cap.
- Client half: one package (`dsh-git-panel`, `dsh.client.platform:'web'`) with a single bundle that registers BOTH entry points: a `main` panel (`sidebar.panellist` + `main`, own 3-column layout: repo picker + worktrees/branches tree + Staged/Unstaged lists | diff viewer | optional repo file tree) and optionally a right-sidebar tab type (`ctx.sidebarRightTabs.register({ id:'git-panel', kind:'git-panel', title: () => t('tab'), guide:[…] })` + body under `sidebar.right.pane.tab`, `keepMounted: true`) for per-Session quick diffs.
- Reuse: `sidebar.files.tree` Factory for every list/tree (changed files, repo browse, worktree/branch tree — feed synthetic `TreeEntry` paths); `sidebar.files.navigator` only if embedding the Files page; documentpreview via `openResource('dsh-resource://file/session/<sessionId>/<path>')` for "open file"; forge-changes tab via `openResource('dsh-resource://forge-changes/<session>/local')` for a read-only "Local changes" fallback when forge is active; `--dsw-alias-file-diff-*` tokens; `ctx.remote.directoryPicker.pick`; `workspaceRegistry.list`; `ctx.worktrees.create` (or `git worktree add` itself if you need a non-Session-attached pool); deliverables review tab pattern (`changes-review` address) for turn-scoped diffs.
- Reimplement: repo registry & picker, Git status/diff parsing (or reuse the forge approach: parse on Host with jsdiff, ship structured hunks), staging mutations, worktree/branch tree presentation, diff rendering (no shipped component export; copy the forge changes-view structure — hunk rows, collapsible context, two-column pairing, line-number gutters — and its tokens), large-file/binary handling, refresh orchestration.
- Risks: (1) **permission model** — `ctx.subprocess` spawns as the host user with no sandbox parameter; only forge-style explicit `sandboxPolicy` confinement gives read-only/workspace-write behavior. Don't assume tool-level sandboxing covers plugin Git. (2) **auth** — raw `webServer.register` has no auth; use `connection.fetch.register`. (3) **watchers/refresh** — no shipped file-watch helper for git; poll `status` on panel focus/explicit refresh + debounce, and use `workspaceFiles.changes` (workspace-scoped only) or `fs.watch` per expanded repo dir sparingly. (4) **huge diffs** — cap bytes/hunks/lines (forge defaults `maxDiffBytes`, `maxUntrackedFiles`, 1,000-line hunk collapse, 5,000-line cap are the proven boundaries); binary detection; submodules (forge passes `--ignore-submodules=dirty`, `--submodule=short`). (5) **paths outside workspace** — file reads via `ctx.fs` are unconfined; validate every path against the selected repo root and never echo absolute host paths into model context. (6) **git availability** — `workspace-changes` treats macOS `/usr/bin/git` developer-tools stub as "no git"; check `rev-parse` result and surface a setup message. (7) **non-git dirs** — repo picker must validate with `rev-parse --show-toplevel`; show "not a checkout" instead of failing. (8) **staging is destructive** — no shipped precedent; require explicit per-file/action clicks, no auto-stage, and persist nothing. (9) **main panel is global, right sidebar is session-scoped** — a repo picker with no Session works in a `main` panel but a right-sidebar Git tab cannot render without a Session (`README.md:152`). (10) **verification** — client inspect is currently unavailable, so plan verification via `cordis_inspect_query` host services plus page-level manual check after install.

## Bottom line

- Right-sidebar Git tab: **supported** by the public `ctx.sidebarRightTabs` + `sidebar.right.pane.tab` path (forge and documentpreview are live proofs); per-Session only, and shipped diff UI is read-only.
- Full Zed-like repo-centric panel: **needs a new plugin** (main panel with own 3-column layout recommended) because no shipped repo picker/staging/branch-tree exists, but the file tree Factory, document preview, authenticated route API, Git-under-policy precedent (forge/workspace-changes), worktree service, and the `--dsw-alias-file-diff-*` palette are all reusable today.
